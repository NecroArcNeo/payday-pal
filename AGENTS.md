## Architecture rules
- Local-first: the app runs with no account. Data lives in an on-device Postgres (PGlite, IndexedDB `meridian-payroll`) opened by the `_authenticated` (ssr:false) layout, which no longer requires sign-in. Only one tab may open it (Web Lock); a second tab shows a blocker.
- Pages read and write only through `src/lib/db` (`useEmployees` etc. in `src/lib/payroll.ts` for reads, `db().insert/update/remove/...` for writes). `db()` is the local store, or the Supabase store when the user picked "Edit cloud directly". Never call `supabase.from(...)` from a page.
- The local schema (`src/lib/db/schema.ts`) mirrors the cloud tables minus `owner_id`. Changing a table means: a new cloud migration, a new appended entry in `LOCAL_MIGRATIONS`, and bumping `SCHEMA_VERSION` in both `schema.ts` and the cloud sync functions.
- Sync is whole-database: push replaces the account's cloud copy, pull replaces this device's copy. Both refuse to overwrite changes from elsewhere without confirmation, and both save a verified backup of whatever they replace (local backups in IndexedDB `meridian-payroll-backups`; cloud backups in `cloud_backups`). Keep it that way: no code path may delete or replace payroll data without a backup first.
- Cloud: every table has `owner_id` (default `auth.uid()`), RLS is owner-only, and keys are `(owner_id, id)`. `push_snapshot` / `pull_snapshot` / `sync_status` (drizzle/migrations/0003) are the sync API; `sync_meta.version` is bumped by triggers on any cloud write.
- Worked hours for clock entries are computed by a DB trigger (`compute_record_hours`) in both the local and cloud databases, so imports and manual entries share one formula.
- File imports are parsed client-side with SheetJS (`xlsx`). The user maps each column to a field and picks the header row and row range per sheet; parsing lives in `src/lib/import/parse.ts` (pure, tested). Excel dates/times are read from cell serials, never from display text. Imports back up first and skip shifts already saved (`recordKey`).
- Theme is a `.dark` class on <html>, set pre-hydration by an inline head script from localStorage.
- Custom employee categories live in employee_field_defs; values in employees.custom_fields keyed by def id (so renames keep data). Pay is computed client-side in `src/lib/pay.ts` (`employeePay`): Saturday/Sunday hours are always overtime (setting `weekend_overtime`), Mon–Fri hours past `ot_threshold` in a Mon–Sun week are overtime, the employee's shift multiplier (`shifts`, `employees.shift_id`, null = first shift) scales the rate, `time_records.pay_override` pays a day exactly that amount, and `employees.pay_type = 'salary'` pays `ot_threshold` hours × rate × shift for each week with records (no overtime), shared across the week's days by hours. Per-record pay (`recordPay`/`payByRecord`, `useRecordPay` in tables) uses the same rules over whole weeks. Payroll loads whole weeks around the period (uncapped) so weekly overtime is right.
- Employee lookups everywhere use `searchEmployees`/`matchesEmployee` (src/lib/employee-search.ts) via `SearchInput` and `EmployeePicker` (src/components/EmployeeSearch.tsx), which take an `EmployeeFilter` (text plus exact department/position dropdowns); use those instead of plain <select>s. Bulk edits/deletes call `backupBefore(...)` first and use the store's `updateMany`/`removeMany`.
- The Time records list pages through the store (`listRecordsPage`, 50 at a time) with filters applied in the database; "Edit all"/"Delete all" act on every matching record via `listRecordsMatching`, not just the loaded page. Dates show their weekday via `weekday()`; use `isoDate()` (local calendar date) rather than `toISOString()` for "today".
